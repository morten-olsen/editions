# Paged article

<div style={{ fontSize: "1.2rem", color: "var(--color-ink-secondary)", lineHeight: 1.625, marginTop: "1rem", marginBottom: "4rem", maxWidth: "65ch" }}>
  A typesetter-model layout engine that renders markdown articles as paginated, magazine-style pages. Every element — title, byline, hero image, drop cap, body text, inline images — is measured with <a href="https://github.com/chenglou/pretext" style={{ color: "var(--color-accent)" }}>pretext</a> and absolutely positioned. No HTML flow, no CSS margins. The layout engine is the designer; pretext is the measuring stick.
</div>

    <p style={{ margin: "0 0 0.75rem" }}>The engine uses a <strong style={{ color: "var(--color-ink)" }}>consumer pattern</strong>. An <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>ArticleContent</code> has top-level metadata (title, hero, author) and a body element array. Each layout function consumes content from the front, produces a page of positioned regions, and returns what remains.</p>
    <p style={{ margin: "0 0 0.75rem" }}>Layout functions are page templates — they act like a magazine designer composing a page within the available estate. New page styles (pull-quote spreads, full-bleed images) are added as new functions with the same signature.</p>
    <p style={{ margin: 0 }}>A <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>Page</code> is a flat array of <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>Region[]</code> — text, image, rule, or separator — each with exact (x, y, width) coordinates. The renderer just paints what it's told.</p>

## Drop cap avoidance

<div style={{ display: "flex", gap: "4rem", marginBottom: "4rem", alignItems: "flex-start" }}>
  <div style={{ width: "22rem", flexShrink: 0 }}>

        <div style={{ marginLeft: "2.2rem" }}>
          <div>or the better part of a decade, the</div>
          <div>dominant paradigm in digital reading</div>
          <div>has been the infinite scroll. Twitter</div>
        </div>
        <div style={{ marginTop: "0.125rem" }}>pioneered it, Facebook perfected it, and RSS readers adopted it wholesale. The assumption was simple: more content, delivered faster.</div>
      </div>
      <div style={{ marginTop: "1rem", padding: "0.5rem 0.75rem", background: "var(--color-surface-sunken)", borderRadius: "0.375rem", fontSize: "0.65rem", fontFamily: "var(--font-mono)", color: "var(--color-ink-tertiary)", lineHeight: 1.6 }}>
        <div>dropcap region: (x:0, y:4, 58px font)</div>
        <div>narrow lines:  (x:dcW, y:0, w:full-dcW)</div>
        <div>full lines:    (x:0, y:3×lh, w:full)</div>
      </div>
    </div>
  </div>
  <div style={{ fontSize: "0.833rem", color: "var(--color-ink-secondary)", lineHeight: 1.625 }}>
    <p style={{ margin: "0 0 0.75rem" }}>The drop cap is not a CSS <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>float</code>. It's a positioned <strong style={{ color: "var(--color-ink)" }}>avoidance element</strong>. The layout engine measures the drop cap character with pretext to determine its exact width, then re-measures the paragraph text using <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>layoutNextLine</code> with a narrower width for the first 3 lines.</p>
    <p style={{ margin: "0 0 0.75rem" }}>This produces three regions: the large character itself, the narrow lines beside it, and the full-width lines below it. Each is absolutely positioned. Because both the drop cap and the body text are measured with pretext against the same font stack, there is no mismatch between measurement and rendering.</p>
    <p style={{ margin: 0 }}>The same <code style={{ fontFamily: "var(--font-mono)", background: "var(--color-surface-sunken)", padding: "0.1rem 0.3rem", borderRadius: "0.2rem", fontSize: "0.8rem" }}>flowTextAroundObstacle</code> helper is used for both drop caps and hero image avoidance — any positioned element that text needs to flow around.</p>

## Usage

<div style={{ fontSize: "0.833rem", color: "var(--color-ink-secondary)", lineHeight: 1.625, marginBottom: "4rem" }}>

```tsx
import { PagedArticleView } from 'components/paged-article/paged-article.ts';

// Drop-in component — measures its container, handles everything
<PagedArticleView article={article} style="feature" footer={<MyFooter />} />

// Or use the engine directly for custom rendering
import { layoutArticle } from 'components/paged-article/paged-article.ts';

const { pages, pageCount, config } = layoutArticle(article, {
  viewport: { width: 1000, height: 800 },
  style: 'feature',
});
// pages is Region[][] — render however you want
```

**ArticleInput** requires `title`, `sourceName`, and `content` (markdown). Optional fields: `author`, `summary`, `publishedAt`, `consumptionTimeSeconds`, `imageUrl`, `sourceType`.

**Styles**: `feature` (hero-led front page), `standard` (clean title + image), `minimal` (compact opener).

**Layout functions** (`openerLayout`, `bodyLayout`) follow the `PageLayoutFn` signature — add new page templates by implementing the same interface.
