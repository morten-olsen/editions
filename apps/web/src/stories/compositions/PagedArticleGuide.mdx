# Writing page layouts

<div style={{ fontSize: "1.2rem", color: "var(--color-ink-secondary)", lineHeight: 1.625, marginTop: "1rem", marginBottom: "4rem", maxWidth: "65ch" }}>
  Page layouts are functions that act as a magazine designer: they receive a blank page and unconsumed article content, compose the page by placing regions at exact coordinates, and return what remains. This guide covers how to write new layouts.
</div>

<div style={{ height: "1px", background: "var(--color-border)", marginBottom: "4rem" }} />

## The signature

<div style={{ marginBottom: "4rem" }}>

Every layout function has the same type:

```ts
type PageLayoutFn = (
  content: ArticleContent,
  config: PageConfig,
) => { page: Page; remaining: ArticleContent };
```

**`content`** is what's left to lay out:
- `content.meta` — article metadata (title, hero, author, etc.), `null` once consumed by an opener
- `content.elements` — body elements (text, image, spacing, hr) consumed front-to-back

**`config`** is the page's physical constraints:
- `width`, `height` — container dimensions (from ResizeObserver, not viewport)
- `padding` — top, bottom, horizontal
- `columns` — 1 or 2
- `columnGap`, `navHeight`, `footerHeight`

**Return**: a `Page` (flat array of positioned `Region[]`) and the `remaining` content for the next layout function.

</div>

<div style={{ height: "1px", background: "var(--color-border)", margin: "4rem 0" }} />

## A minimal example

<div style={{ marginBottom: "4rem" }}>

Here's a layout that places a centered pull-quote from the first blockquote element, with body text flowing in columns below:

```ts
import { layoutWithLines } from '@chenglou/pretext';
import { getPrepared, SERIF_STACK } from './paged-article.measure.ts';

const pullQuoteLayout: PageLayoutFn = (content, config) => {
  const cw = contentWidth(config);
  const regions: Region[] = [];
  let y = 0;
  let elements = content.elements;

  // Find and consume the first blockquote
  const bqIdx = elements.findIndex(
    (el) => el.kind === 'text' && el.variant === 'blockquote',
  );

  if (bqIdx >= 0) {
    const bq = elements[bqIdx] as TextElement;
    const quoteFont = `italic 24px ${SERIF_STACK}`;
    const prepared = getPrepared(bq.text, quoteFont);
    const maxW = Math.min(cw, 500);
    const result = layoutWithLines(prepared, maxW, 36);

    // Center the quote horizontally
    const quoteX = (cw - maxW) / 2;

    regions.push({
      kind: 'text',
      x: quoteX, y, width: maxW,
      text: bq.text,
      inlineSpans: bq.inlineSpans,
      allLines: result.lines,
      font: quoteFont,
      lineHeight: 36,
      startLine: 0,
      endLine: result.lineCount,
      role: 'blockquote',
    });

    y += result.height + 36; // generous gap after quote

    // Remove the blockquote from elements
    elements = [...elements.slice(0, bqIdx), ...elements.slice(bqIdx + 1)];
  }

  // Flow remaining body content below
  const { regions: bodyRegions, remaining } = flowIntoColumns(elements, y, config);
  regions.push(...bodyRegions);

  return {
    page: { regions },
    remaining: { meta: content.meta, elements: remaining },
  };
};
```

## How the engine chains layouts

<div style={{ fontSize: "0.833rem", color: "var(--color-ink-secondary)", lineHeight: 1.625, marginBottom: "4rem" }}>

```ts
const layouts: PageLayoutFn[] = [
  openerLayout('feature'),  // page 1: title + hero + drop cap + columns
  bodyLayout,               // page 2+: repeated until content is empty
];

const pages = buildPages(content, config, layouts);
```

The first layout in the sequence handles page 1. The second handles page 2. When the sequence runs out, **the last layout repeats** for all remaining pages. So `[openerLayout, bodyLayout]` means: one opener page, then as many body pages as needed.

You can insert specialty layouts in the middle:

```ts
const layouts: PageLayoutFn[] = [
  openerLayout('feature'),   // page 1
  pullQuoteLayout,           // page 2: featured blockquote
  bodyLayout,                // page 3+: repeated
];
```

The engine stops when `remaining.meta` is null and `remaining.elements` is empty.

## File structure

<div style={{ fontSize: "0.833rem", color: "var(--color-ink-secondary)", lineHeight: 1.625, marginBottom: "4rem" }}>

```
paged-article/
  paged-article.ts              ← public API (import from here)
  paged-article.segments.ts     ← markdown → typed segments
  paged-article.measure.ts      ← pretext measurement, font stacks, cache
  paged-article.layouts.ts      ← types + layout functions (you write these)
  paged-article.engine.ts       ← prepare + build loop + responsive config
  paged-article.render.tsx      ← React renderer for Region[]
  paged-article.hooks.ts        ← container size, font loading
  paged-article.view.tsx        ← drop-in React component
```

New layout functions go in `paged-article.layouts.ts`. Export them and add to the layout sequence in `paged-article.engine.ts` (or let the consumer pass a custom sequence).
